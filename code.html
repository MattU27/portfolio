Problem & Scope
Eliminating Paper & Disjointed Spreadsheet Tenders

Procurement submissions historically suffered severe operational drag: manual document intake, vulnerability to missing vendor compliance certificates, and protracted manual verification across executive desks. My responsibility was delivering an internal system that formalized the rules into a dependable digital state machine.

Relational Integrity PostgreSQL foreign keys ensure no orphan supplier documents exist.
Granular RLS Strict Supabase Row Level Security prevents cross-bidder leakage.
Zero Data Loss Transactional commits with complete audit history for every vote.
Workflow Logic
End-to-End Bidding Sequence
  1. 01.
    Vendor Proposal Submission: Suppliers upload notarized envelopes and quote sheets validated against pre-set schema rules before database insertion.
  2. 02.
    Automated Compliance Gate: System checks statutory certificates, expiry timelines, and bonding credentials automatically. Non-compliant bids fail closed.
  3. 03.
    Multi-Tier Approval Matrix: Parallel or sequential department evaluations based on tender budget tier, requiring multi-signature approval.
  4. 04.
    Audit Trail & Post-Award: Irreversible logging captures timestamps, reviewer IP hashes, and outcome notifications for institutional transparency.
Engineering Rationale
Database Integrity Over Flexible Schemas

For fiscal procurement, document databases represent undue operational risk. I selected PostgreSQL hosted on Supabase to leverage native ACID transactions, strict foreign keys, and performant Row Level Security (RLS) policies. On the application layer, TypeScript type guards evaluate server action payloads prior to any transactional write, rejecting non-conforming bidding envelopes at the perimeter.

Operational Retrospective
Clarity Over Cleverness for Enterprise Users

Enterprise administrative teams prioritize explicit confirmation over hidden automations. Introducing clear visual feedback states for asynchronous multi-part uploads reduced support queries drastically. Additionally, investing time in third normal form (3NF) relational schema modeling early prevented messy data migrations when committee requirements evolved mid-cycle.

Problem & Environment
Replacing Fragmented Logistics Dispatch

Logistics coordinators had to reconcile disparate telephone confirmations, handwritten delivery receipts, and disconnected tracking sheets. The goal was to establish an authoritative source of truth for consignment status, driver handoffs, and customer drop-offs with verifiable Proof-of-Delivery (POD).

Indexed Lookups PostgreSQL B-Tree indexes on tracking numbers ensure instant lookup.
Three-Role Security Isolated permissions for Field Drivers, Coordinators, and Management.
Optimistic Cache Smooth UI transitions with rollback resilience for spotty cellular connections.
Operational Pipeline
From Manifest Creation to Final Drop-off
  1. 01.
    Consignment Creation: Dispatchers generate tracked parcels with origin, recipient metadata, and custom handling directives.
  2. 02.
    Dispatch Assignment: Consignments are batched to vehicles or couriers with automated load and weight validation.
  3. 03.
    In-Transit Checkpoints: Sequential milestone logging keeps both internal teams and recipient inquiries updated.
  4. 04.
    Proof-of-Delivery Verification: Drivers upload recipient signatures and photo receipts, immutably timestamped in the PostgreSQL record.
Technical Architecture
Resilient State Under Intermittent Conditions

Mobile users in logistics environments often face inconsistent mobile broadband. I implemented optimistic UI updates in React backed by local rollback safeguards. PostgreSQL compound indexes were placed on status and date ranges to ensure high-volume historical queries execute in under 35 milliseconds.

Iterative Methodology
Direct Spreadsheet Feedback Triage

Rather than forcing non-technical logistics staff into complex bug trackers, I established a collaborative Google Sheet where operators flagged discrepancies and usability hurdles in real-time. This pragmatic triage rhythm allowed me to push targeted fixes and UX micro-optimizations within 24-hour cycles during the critical system launch phase.
